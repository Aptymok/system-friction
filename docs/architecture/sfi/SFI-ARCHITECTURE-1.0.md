# System Friction Institute Architecture 1.0

**Contract:** `SFI-ARCHITECTURE-1.0`  
**Status:** FROZEN

System Friction Institute (SFI) is not a collection of modules, an AI company, or a family of unrelated SaaS products. It is one institutional architecture for observing, modelling, intervening and learning from complex systems. Commercial delivery configures that capacity as tenant-scoped cases, service profiles and governed reports.

## Case Platform

`SFI_CASE_V1` coordinates canonical references. It is not a source store, evidence store or institutional-memory store. Client case memory is tenant-scoped and can enter the institute only through `SFI-CASE-TO-INSTITUTION-GATE-1.0`.

```text
CLIENT → TENANT → CASE PLATFORM → governed SFI capabilities
```

The following routes are constitutionally forbidden:

```text
CLIENT → ROOT
COMMERCIAL RESULT → INSTITUTIONAL TRUTH
AI OUTPUT = EVIDENCE
REPORT OUTPUT = EXECUTION AUTHORITY
```

The operational enterprise assurance chain can preserve governed relations across:

```text
TENDER → SUPPLIER → CONTRACT → DELIVERY → ASSET / SERVICE
→ HELP DESK → SLA → WARRANTY → RETURN → SUPPLIER HISTORY → NEXT TENDER
```

No confidential employer or client data belongs in the public SFI repository. Public code contains generic contracts and synthetic/public fixtures; authorized operational data must enter through controlled private/local ingestion.

