# SFI Methodology and Observation Canon

Status: canonical proposal for ACP ratification inside PR #159. This document must govern ROOT before further visual or data integration.

## 1. Foundational rule

SFI does not expose a single undifferentiated score. It observes different classes of entities with different instruments under the MIHM umbrella. Each instrument must preserve object identity, temporal window, evidence lineage, formula version, confidence and epistemic status.

ROOT must never combine values from different instruments as though they measured the same object. It may compare them only through an explicit cross-instrument interpretation layer.

## 2. Canonical hierarchy

### 2.1 MIHM

MIHM is the meta-methodological framework. It defines the common measurement grammar:

- IHG: integrity or cohesion of governance/structure for the observed object;
- NTI: intensity and traceability of interaction or signal transmission;
- LDI: longitudinal dissipation, decay or loss of continuity;
- xi: bounded residual uncertainty/noise, never an arbitrary decorative constant;
- Phi: homeostatic or continuity state for one explicitly identified object and instrument;
- F_s: systemic friction, canonically `1 - Phi` when Phi is computed by the SFI Math Core;
- regime: HOMEOSTATICO, CRITICO or ENTROPICO;
- evidence lineage, observation time, confidence and warnings.

The ratified generic SFI Math Core is:

`Phi = clamp01((IHG * NTI) / (1 + LDI) + xi)`

`F_s = clamp01(1 - Phi)`

Default `xi = 0.03` is permitted only when the instrument declares that xi was not observed and the output is marked DERIVED/THIN. An observed or calibrated xi supersedes the default.

Regime thresholds are those implemented in `src/lib/sfi/math.ts` until ACP changes them:

- HOMEOSTATICO: Phi >= 0.58, LDI <= 0.45, NTI >= 0.55, IHG >= 0.50;
- ENTROPICO: Phi <= 0.22, or LDI >= 0.78, or NTI <= 0.25;
- otherwise CRITICO.

### 2.2 Instruments under MIHM

There are four primary observational instruments currently represented in code:

1. MOP-H — personal/session instrument.
2. ScoreFriction — bounded object/signal friction instrument.
3. World Vector / WorldSpect — world-scale contextual instrument.
4. PPOI — longitudinal phenomenon instrument.

These are not interchangeable methodologies and their Phi symbols are not interchangeable values.

Operational protocols such as AMV, ACP, evidence registry, cognitive runtime, prediction and institutional memory are not additional measurement methodologies. They collect, govern, execute, validate or preserve observations generated by the instruments.

## 3. Instrument definitions

### 3.1 MOP-H

Canonical object: one identified person/session at one bounded observation interval.

Purpose: observe the relation between personal/internal governance, interaction or cognitive load, longitudinal dissipation, goal orientation and residual perturbation.

Current variables:

- IHG;
- NTI;
- LDI;
- GO;
- EPSILON.

Current output symbol: `PHI_PERSONAL` / Phi_p.

Use MOP-H when:

- a person begins or returns to an SFI process;
- a pre/post intervention personal state is needed;
- the system must compare one person's trajectory across sessions;
- a case requires distinguishing personal state from organizational or world context.

Do not use MOP-H to score a company, a public crisis, a cultural object or the world.

Important conflict: `src/lib/moph/moph-math.ts` uses a specialized inverse formula rather than the generic SFI Math Core. Therefore Phi_p is an instrument-specific personal index, not the global Phi_SF. ROOT must label it as `Phi_p · MOP-H`, show its formula reference and never substitute it for institutional Phi_SF.

Activation requirement: a valid session ID and measured inputs. There is no meaningful global latest MOP-H value across all users. ROOT may show active/open personal sessions, but not fabricate a single institutional Phi_p.

### 3.2 ScoreFriction

Canonical object: one bounded artifact, signal, media object, software object, event representation or observation package.

Purpose: characterize friction and continuity within an analyzable object using available acoustic, semantic, memetic, platform and cultural vectors.

Current persisted source: `scorefriction_vectors`, linked to `scorefriction_observations`.

Use ScoreFriction when:

- an uploaded or registered object must be measured;
- Studio needs a formal report about an audio, text, image, software or cultural object;
- objects must be compared longitudinally or across versions;
- a case requires evidence about the formal behavior of an artifact rather than the entire organization.

Do not use ScoreFriction as an automatic score of the whole institute, a company or the world unless the observed object is explicitly an institutional snapshot assembled for that purpose.

Canonical output: `Phi_s · ScoreFriction`, plus IHG, NTI, LDI and F_s for the object.

Critical conflict: `src/lib/evaluator/derivedMihmRuntime.ts` currently derives IHG/NTI/LDI/F_s/Phi through heuristic weighted formulas that conflict with `src/lib/sfi/math.ts`, including an F_s definition that is not always `1 - Phi`. Those values must be classified as LEGACY_DERIVED until migrated. ROOT must not present them as canonical Phi_SF. The correct migration is:

1. retain vector feature derivation;
2. document how vectors resolve to IHG, NTI, LDI and xi;
3. calculate Phi and F_s through the SFI Math Core;
4. preserve the old formula version for historical reproducibility.

### 3.3 World Vector / WorldSpect

Canonical object: a timestamped world-context snapshot over declared domains and sources.

Purpose: observe exogenous context in which SFI cases and entities operate. It is a contextual field, not a diagnosis of one person, company or object.

Current adapter source: latest `worldspect_snapshot` through `getLatestWorldSpectSnapshot()`.

Current variables exposed by the adapter:

- WSI;
- NTI;
- confidence;
- degraded sources.

Current output symbol: `PHI_WORLD` / Phi_w, presently mapped to WSI.

Use World Vector when:

- ROOT needs the present external context;
- a case must be compared against macroeconomic, political, technological, cultural, environmental, health, information or social conditions;
- the system needs to determine whether a pattern is local, sectoral or globally reinforced;
- scenario and recurrence analysis needs exogenous pressure.

Do not use World Vector to decide that a specific actor is responsible or that a specific intervention will work without case evidence.

World Vector must show:

- domain breakdown;
- source inventory;
- source freshness;
- source failures/degradation;
- dominant signals;
- confidence;
- snapshot timestamp;
- trajectory against previous snapshots.

Critical requirement: ROOT must consume the WorldSpect snapshot/domain breakdown, not generic evidence-node confidence. If no snapshot exists, the cause must be visible: no daily cycle, source ingestion failure, persistence failure or stale snapshot.

Phi_w is a contextual homeostatic/world-state index. It is not Phi_SF for the institute and must not be combined with Phi_p, Phi_s or Phi_f through an undocumented average.

### 3.4 PPOI

Canonical object: a named phenomenon that persists through time and accumulates heterogeneous evidence.

Purpose: open, maintain, recalibrate and eventually close a longitudinal phenomenon record. PPOI exists for cases where the object cannot be understood from one artifact or one instant.

Current persisted entities:

- `ppoi_phenomena`;
- `ppoi_evidence`;
- `ppoi_hypotheses`;
- `ppoi_evidence_links`.

PPOI accepts evidence types including text, audio, video, image, software, dataset, interview, field observation, model, paper, conversation and institutional record. Each new item triggers recalibration, trajectory inference and a current/rival hypothesis.

Use PPOI when:

- a case has a durable question or anomaly;
- multiple evidence items arrive over days or months;
- competing hypotheses must remain visible;
- an intervention must be followed longitudinally;
- the institute needs to know whether a phenomenon persists, transforms, resolves or recurs.

Do not use PPOI for a one-off object that only needs ScoreFriction, or for a personal session that only needs MOP-H.

Canonical output: `Phi_f · PPOI` only when the PPOI composite has been calibrated and its semantic meaning is declared. Until then, the database field `current_composite` is a phenomenon composite and must not be silently equated with global Phi_SF.

PPOI is currently underused because the system can create and recalibrate phenomena but ROOT does not yet route open cases into PPOI automatically. The missing mechanism is a Method Selection Resolver and case-to-phenomenon lifecycle.

## 4. Institutional Phi_SF

Phi_SF belongs to one explicit institutional/system object and a timestamped snapshot. It must be computed from canonical IHG, NTI, LDI and xi produced by the institutional observation cycle, not selected from whichever instrument has a number.

Canonical source candidate already exists: `sfi_indicator_snapshots`, populated by the world/interface operational state through `persistIndicatorSnapshot()`.

Required rows for ROOT:

- `sfi-ihg`;
- `sfi-nti`;
- `sfi-ldi`;
- `sfi-wsv`;
- `sfi-xi`;
- `sfi-phi-sf`;
- `sfi-fs`;
- `sfi-regime`.

Each row must include source, captured_at, source_status, warnings, formula version and evidence lineage.

If xi is not persisted, Phi_SF may be calculated with xi=0.03 only as DERIVED_THIN and ROOT must disclose that default. A future calibrated xi must be linked to residual disagreement, source variance or unexplained error; it must not be manually selected for visual convenience.

## 5. Method Selection Resolver

Every case or observation must be routed according to object class and question.

- Person/session question -> MOP-H.
- Bounded artifact/signal/object question -> ScoreFriction.
- External contextual/world question -> World Vector.
- Persistent multi-evidence phenomenon/case -> PPOI.
- Institutional operating state -> canonical Phi_SF snapshot.
- Mixed case -> PPOI is the longitudinal container; MOP-H, ScoreFriction and World Vector become linked measurements, not replacements for PPOI.

A case may use multiple instruments, but one must be designated PRIMARY and the others CONTEXTUAL, SUPPORTING or CONTRAST.

## 6. Case lifecycle

ROOT must observe cases through this sequence:

1. Proposed signal/case.
2. Qualification: actor, object, temporal window, crisis/pain, confidence and evidence sufficiency.
3. Method selection.
4. Open PPOI phenomenon when persistence or multi-evidence follow-up is required.
5. Attach instrument runs:
   - MOP-H session;
   - ScoreFriction object analysis;
   - World Vector contextual snapshot;
   - other evidence.
6. Current and rival hypothesis.
7. Evidence debt and missing inputs.
8. Proposed intervention/strategy.
9. Governance decision.
10. Execution.
11. Re-observation.
12. Outcome and recurrence assessment.
13. Closure, continuation or strategy change.
14. Institutional memory and public/private report.

ROOT must prioritize open cases that belong to the founder/institute, cases with overdue evidence, decisions without action, actions without re-observation and high-confidence external cases awaiting method assignment.

## 7. ROOT presentation contract

ROOT is the institutional operational instrument. It must not show an unexplained number.

For each displayed metric/instrument it must expose:

- observed object;
- methodology/instrument;
- value and symbol;
- formula/version;
- source tables/services;
- observation timestamp and age;
- confidence;
- epistemic status: OBSERVED, DERIVED, INFERRED, THIN, DEGRADED, MISSING or CONFLICTED;
- evidence lineage;
- reason for absence;
- process that generates it;
- available corrective action;
- linked open cases.

The first screen should contain:

- System Friction Institute · Operacional;
- canonical Phi_SF, F_s, IHG, NTI, LDI, xi and regime;
- current World Vector context;
- open/qualified cases;
- PPOI phenomena requiring evidence or recalibration;
- object analyses awaiting ScoreFriction;
- active personal sessions where relevant, without global aggregation;
- site/surface health;
- agent/runtime health;
- governance and execution debt;
- possible interested actors;
- Project Execution Manager priorities;
- source and data-quality diagnostics.

Instrument-specific visuals may remain, but a visual must be suspended or relabeled when its data contract is absent. A proxy may be shown only with the label PROXY/DERIVED and an explanation.

## 8. Resolved interpretation of existing visuals

- Phi regime rings: canonical Phi_SF only.
- Friction field: derived visualization from Phi_SF/F_s plus evidence relationships; not valid from Phi alone when graph relationships are absent.
- Cognitive Twin: entity-specific construct, never a generic decorative blend. Requires selected entity and linked state/evidence.
- World Spectrum: WorldSpect domain breakdown only.
- Longitudinal tension: derived case/phenomenon trajectory; valid only when there are at least two comparable observations.
- Semantic pressure: must come from explicit semantic contradiction/ambiguity/saturation measures; evidence count alone is invalid.
- Stochastic projection: prediction runs/scenarios with assumptions and uncertainty; a decorative branch fan is invalid.
- Agent entropy: may be defined as runtime state dispersion only after a formula is adopted; until then label Runtime Degradation.
- Living chronology: event/evidence/intervention/outcome timeline with severity or confidence, not ordinal index alone.
- Operational log: audit/governance/execution events; currently conceptually valid.

## 9. Conflicts that must block final ROOT integration

1. Generic SFI Math Core versus ScoreFriction legacy heuristic formulas.
2. Phi_p specialized MOP-H formula versus generic Phi semantics.
3. PPOI `current_composite` being displayed as Phi_f without an explicit calibration definition.
4. Phi_w currently equal to WSI without a documented relationship to IHG/NTI/LDI.
5. Missing canonical reader for `sfi_indicator_snapshots`.
6. Missing persisted/calibrated xi.
7. ROOT visual proxies currently named as full methodologies.
8. No central Method Selection Resolver.
9. No automatic linkage from qualified/open cases to PPOI and instrument runs.

These conflicts do not justify inventing values. They require explicit CONFLICTED/MISSING states and tracked remediation.

## 10. Implementation order

1. Ratify this canon through ACP.
2. Implement a Methodology Registry and Method Selection Resolver using existing contracts/tables.
3. Add canonical `sfi_indicator_snapshots` reader and Phi_SF calculation through `src/lib/sfi/math.ts`.
4. Version and classify ScoreFriction legacy derivation; migrate new calculations to Math Core.
5. Define/calibrate PPOI composite semantics before naming it Phi_f in ROOT.
6. Document WorldSpect source registry and map domain breakdown into ROOT.
7. Add case-to-PPOI/instrument linkage and evidence debt.
8. Replace invalid visual proxies with canonical data or explicit suspended states.
9. Only then complete and merge ROOT.

No additional methodology should be created merely to fill a panel. New formulas require ACP authorization and versioned historical reproducibility.
