## 4.2 FORMULAS CANONICAS

PHI_SFI = (IHG * NTI) / (1 + LDI) + XI
PROPIETARIO: MIHM
ESTADO: FALTANTE

F_S = 1 - PHI_SFI
PROPIETARIO: MIHM
ESTADO: EXISTE

PSI_MOPH = ((1/(IHG+0.1)) * NTI * (1/(LDI+0.1)) + EPSILON - 0.15*GO) / 12
PROPIETARIO: MOPH
ESTADO: FALTANTE

C_FIELD = IHG * (1-LDI) * (1-0.35*NTI)
PROPIETARIO: MIHM
ESTADO: EXISTE

D_M = 1 - EXP(-(LN(2)/HALFLIFE)*AGE)
PROPIETARIO: MEMORY
ESTADO: EXISTE

W_10 = AGGREGATE(OBSERVATIONS, TRUST, PRIORITY)
PROPIETARIO: WORLDSPECT
ESTADO: FALTANTE

IHG = (1/N) * SUM(C_I - E_I) * (1 - L_I)
PROPIETARIO: MIHM
ESTADO: EXISTE

NTI = (1/5) * [(1-LDI_N) + ICC_N + CSR + IRCI_N + IIM]
PROPIETARIO: MIHM
ESTADO: EXISTE

LDI = (1/N) * SUM(DELTA_TI / T_REFERENCIA)
PROPIETARIO: MIHM
ESTADO: EXISTE

## 4.3 REGIMENES

HOMEOSTATIC: PHI_SFI > 0.60
TRANSITION: 0.30 < PHI_SFI <= 0.60
CRITICAL: PHI_SFI <= 0.30

## 8B.1 PROPÓSITO

LA ONTOLOGIA INSTITUCIONAL DEFINE QUE ENTIDADES PUEDEN EXISTIR DENTRO DEL UNIVERSO SFI Y QUE RELACIONES SON VALIDAS ENTRE ELLAS.

EL PROPOSITO DE ESTA ONTOLOGIA ES GARANTIZAR:

CONSISTENCIA SEMANTICA
NAVEGACION UNIFORME

## 8B.3 DEFINICIÓN DE ENTIDADES

**PHENOMENON**

REPRESENTA CUALQUIER SISTEMA, COMPORTAMIENTO, CONDICION O PROCESO OBSERVADO.

EJEMPLOS: INFLACION, MERCADO DE VIVIENDA, MOVILIDAD URBANA, ADOPCION TECNOLOGICA, GOBERNANZA DE IA, PRODUCTIVIDAD ORGANIZACIONAL

PREGUNTA FUNDAMENTAL: ¿QUE ESTA OCURRIENDO?

**OBSERVATION**

REGISTRO DE UN HECHO OBSERVADO. NO CONTIENE INTERPRETACION. CONTIENE CAPTURA.

EJEMPLOS: IPC AUMENTA 0.8%, TIEMPO PROMEDIO DE TRASLADO AUMENTA, VENTAS DISMINUYEN 12%

PREGUNTA: ¿QUE FUE OBSERVADO?

**EVIDENCE**

INTERPRETACION EVALUADA DE UNA O MAS OBSERVACIONES.

EJEMPLOS: EXISTE PRESION INFLACIONARIA PERSISTENTE, LA CONGESTION URBANA AFECTA LA PRODUCTIVIDAD, LA CAIDA DE VENTAS COINCIDE CON MENOR DEMANDA

PREGUNTA: ¿QUE EVIDENCIA EXISTE?

**HYPOTHESIS**

MODELO EXPLICATIVO PROVISIONAL.

EJEMPLO: LA INFLACION ACTUAL ES IMPULSADA PRINCIPALMENTE POR COSTOS LOGISTICOS.

PREGUNTA: ¿POR QUE PODRIA ESTAR OCURRIENDO?

**PREDICTION**

PROYECCION VERIFICABLE SOBRE ESTADOS FUTUROS.

EJEMPLO: INFLACION SUPERIOR AL 6% EN SEIS MESES.

PREGUNTA: ¿QUE PODRIA OCURRIR?

**GOVERNANCE_DECISION**

RESOLUCION INSTITUCIONAL AUTORIZADA.

EJEMPLO: APROBAR INTERVENCION, RECHAZAR PROPUESTA, ESCALAR INVESTIGACION.

PREGUNTA: ¿QUE DECIDIMOS HACER?

**MEMORY**

APRENDIZAJE INSTITUCIONAL PERSISTENTE.

EJEMPLO: LA ESTRATEGIA X REDUJO FRICCION LOGISTICA, LA HIPOTESIS Y FUE REFUTADA.

PREGUNTA: ¿QUE APRENDIMOS?

**AGENT**

CAPACIDAD COGNITIVA ESPECIALIZADA.

EJEMPLOS: EVIDENCE HUNTER, TEMPORAL RESOLVER, RISK AGENT, METAORCHESTRATOR

PREGUNTA: ¿QUIEN INTERVINO?

**AGENT_EXECUTION**

INSTANCIA CONCRETA DE TRABAJO REALIZADO POR UN AGENTE.

PREGUNTA: ¿QUE HIZO EL AGENTE?

**CAPABILITY**

FUNCION INSTITUCIONAL QUE PUEDE EJECUTARSE.

EJEMPLOS: EVIDENCE EVALUATION, TRAJECTORY PROJECTION, RISK ASSESSMENT

PREGUNTA: ¿QUE PUEDE HACERSE?

**ORGANIZATION**

ENTIDAD INSTITUCIONAL OBSERVADA.

EJEMPLOS: EMPRESA, UNIVERSIDAD, MUNICIPIO, SECRETARIA, INSTITUCION PUBLICA

PREGUNTA: ¿SOBRE QUE ORGANIZACION EXISTE CONOCIMIENTO?

**REPORT**

TOMOGRAFIA INSTITUCIONAL GENERADA POR SFI.

PREGUNTA: ¿QUE CONOCIMIENTO FUE SINTETIZADO?

**FORMULA**

REPRESENTACION MATEMATICA INSTITUCIONAL.

EJEMPLOS: PHI_SFI, PSI_MOPH, W_10, IHG

PREGUNTA: ¿COMO SE CALCULA?

**EVENT**

HECHO INSTITUCIONAL REGISTRADO.

PREGUNTA: ¿QUE OCURRIO DENTRO DEL SISTEMA?

**STATE**

ESTADO INSTITUCIONAL EN UN MOMENTO ESPECIFICO.

PREGUNTA: ¿COMO ESTABA EL SISTEMA?

**REQUEST**

SOLICITUD DE OPERACION.

PREGUNTA: ¿QUE FUE SOLICITADO?

**OPERATION**

EJECUCION INSTITUCIONAL RASTREABLE.

PREGUNTA: ¿QUE PROCESO SE EJECUTO?

# PARTE XVIII — PRINCIPIO FUNDAMENTAL DEL OBSERVATORIO

## 18.1 DEFINICIÓN FINAL

SFI no es un sistema de indicadores.
SFI no es una plataforma de dashboards.
SFI no es una herramienta de analítica.
SFI no es un repositorio documental.

**SFI es un Observatorio Cognitivo Institucional.**

Su propósito es observar, interpretar, registrar y representar sistemas complejos mediante la trazabilidad completa entre realidad, observación, evidencia, decisión y memoria.

## 18.2 UNIDAD FUNDAMENTAL

La unidad fundamental de SFI no es la pantalla.
La unidad fundamental de SFI no es el reporte.
La unidad fundamental de SFI no es el indicador.

**La unidad fundamental de SFI es ENTITY.**

Toda entidad debe ser:
- Identificable
- Trazable
- Versionable
- Auditable
- Relacionable
- Navegable

## 18.3 PRINCIPIO DE OBSERVACIÓN

Toda información representada por SFI debe poder responder:

- ¿Qué ocurrió?
- ¿Por qué ocurrió?
- ¿Qué evidencia lo respalda?
- ¿Qué agentes participaron?
- ¿Qué decisiones derivaron?
- ¿Qué memoria produjo?
- ¿Qué trayectoria proyecta?

Si una interfaz no puede responder esas preguntas, no cumple la arquitectura SFI.

## 18.4 PRINCIPIO DE TRAZABILIDAD

Toda entidad debe poder recorrerse en ambos sentidos:

```
Reality → Observation → Evidence → Prediction → Decision → Memory
```

y

```
Memory → Decision → Prediction → Evidence → Observation → Reality
```

La trazabilidad es bidireccional.

## 18.5 PRINCIPIO DE MEMORIA

SFI no almacena información. Almacena aprendizaje institucional.

El objetivo final de cada operación es producir **Institutional Memory**.

La memoria es el único mecanismo autorizado para que el sistema aprenda.

## 18.6 PRINCIPIO DE FRICCIÓN

El objeto de estudio de SFI no son los indicadores. El objeto de estudio son las fricciones que producen los indicadores.

Por lo tanto:
- Dato → NO es el fin.
- Indicador → NO es el fin.
- Dashboard → NO es el fin.
- **Fricción → Sí es el fin.**

Toda observación debe conducir a la identificación de:
- Fricciones
- Retroalimentaciones
- Capacidad adaptativa
- Trayectorias
- Posibles intervenciones

## 18.7 PRINCIPIO DE REPRESENTACIÓN

Las interfaces SFI no representan estados. Representan sistemas.

No muestran números aislados. Muestran:
- Relaciones
- Dependencias
- Tensiones
- Retroalimentaciones
- Trayectorias
- Memoria

## 18.8 PRINCIPIO DE UNICIDAD

Existe un único modelo institucional.
Existe un único Entity Graph.
Existe un único sistema de memoria.
Existe una única gobernanza.
Existe una única trazabilidad.

Todas las vistas observan el mismo sistema.

## 18.9 PRINCIPIO DE LAS VISTAS

Las vistas son instrumentos especializados. No constituyen dominios independientes.

- **Atlas** responde: ¿Cómo se conecta todo?
- **WorldSpect** responde: ¿Qué está ocurriendo?
- **MIHM** responde: ¿Cuál es el estado sistémico?
- **Ledger** responde: ¿Qué aprendimos?
- **Governance** responde: ¿Qué debemos decidir?
- **Command Center** responde: ¿SFI converge hacia su atractor?

Pero todas observan el mismo universo institucional.

## 18.10 DEFINICIÓN DEL ENTITY GRAPH LAYER

El Entity Graph Layer es la representación institucional unificada de la realidad observada.

Toda entidad institucional existe dentro del Entity Graph.
Toda navegación debe originarse o terminar en el Entity Graph.
Ninguna interfaz puede construir modelos paralelos.

## 18.11 DEFINICIÓN DEL FRICTION FIELD

El Friction Field es la representación visual canónica de SFI.

No es una gráfica. No es una red. No es un dashboard.

Es una representación dinámica de tensiones entre entidades institucionales.

Cada relación debe expresar:
- Magnitud
- Dirección
- Estabilidad
- Confianza
- Evidencia
- Impacto sistémico
- Velocidad de cambio

## 18.12 DEFINICIÓN DE ÉXITO

SFI se considera exitoso cuando puede:

- Observar sistemas complejos.
- Transformar observaciones en evidencia.
- Transformar evidencia en conocimiento.
- Transformar conocimiento en decisiones.
- Transformar decisiones en memoria.
- Transformar memoria en adaptación institucional.

## DEFINICIÓN CANÓNICA DEFINITIVA

**SYSTEM FRICTION INSTITUTE (SFI)**

SFI es un **Observatorio Cognitivo Institucional** basado en un **Entity Graph Layer** unificado.

Su función es transformar realidad observada en memoria institucional trazable mediante un ciclo continuo de observación, evidencia, razonamiento, decisión y aprendizaje.

Las interfaces SFI no son dashboards. Son instrumentos de observación especializados que permiten explorar un mismo conocimiento institucional desde distintas perspectivas operativas, analíticas, predictivas y estratégicas.

El objeto central de SFI no son los datos, los indicadores ni los reportes.

**El objeto central de SFI es el campo de fricciones que determina el comportamiento de sistemas complejos.**
