## Development carry-forward rule

A requirement already present in the Master Program or a canonical Definition of Done remains valid program debt until fresh evidence classifies it as:

```text
SATISFIED
PARTIAL
MISSING
EXTERNAL_ACTION
SUPERSEDED_BY_AUTHORIZED_DECISION
```

Existing declared debt does not need a new defect or external request to justify completion.

New work outside the existing canonical program requires evidence before implementation.

```text
DECLARED PROGRAM GAP != NEEDS NEW TRIGGER
NEW UNPLANNED FEATURE == NEEDS EVIDENCE/TRIGGER
```

## Legitimate sources of new work

For work outside already-declared program completion debt:

1. production and CI telemetry;
2. Observatory and RETURN evidence;
3. real external cases, revenue experiments and partner requests;
4. research contradictions or reproducibility failures;
5. technology-watch findings with measurable relevance to an existing SFI capability;
6. security, privacy, rights, legal or platform changes affecting current operation;
7. explicit constitutional or institutional decisions.

## Technology watch

Technology scanning is a periodic institutional function, not continuous feature churn. A valid output contains:

- observed external change;
- source/evidence;
- affected existing owner;
- measurable benefit or risk reduction;
- compatibility with frozen contracts;
- migration/deprecation requirement;
- cost and operational burden;
- explicit `NO_ACTION` option.

A technology finding does not authorize implementation by itself.

## Development autonomy

SFI maintains two development inputs:

```text
A. PROGRAM COMPLETION QUEUE
   unsatisfied canonical requirements already declared

B. OBSERVED-TRIGGER QUEUE
   defects, measured frictions, external cases, technology changes
```

Both route through the same owner / assurance / integration system. The founder should not need to remember which chat, agent or workstream to wake up.

Automatic development authority remains bounded by existing authority classes. No model, agent or workflow may self-grant institutional authority, bypass assurance, silently alter constitutional contracts or fabricate external publication/registration evidence.

## Institutional lanes

```text
ENGINEERING / RUNTIME
RESEARCH / OBSERVATORY
EXTERNAL / COMMERCIAL
FOUNDER / GOVERNANCE
MATERIAL / STUDIO
```

Cross-lane evidence may trigger another lane. Work is not moved into engineering merely because software could be built for it.

## Founder-away criterion

R4 succeeds progressively when:

- declared development debt is reconstructable and routed without founder memory;
- routine defects are detected and routed without founder polling;
- technology changes generate bounded proposals rather than founder research debt;
- external signals are captured with provenance and routed to the correct lane;
- implementation is performed by owner, assured independently and integrated through SFI-00;
- the founder is asked only for decisions requiring founder/institutional authority;
- SFI can explain why work exists, who owns it, whether it came from program debt or new evidence, and what RETURN closed it.

## Anti-expansion rule

R4 does not add a ninth workstream. It does not create a universal super-agent. It does not convert every institutional function into an autonomous software agent. It does not erase unfinished work because a prior round ended. Reuse existing owners first; complete declared contracts; add architecture only when evidence proves an owner is missing.
